1. Communication Rules & Channels   
   >Daily Sync (WhatsApp): 15-minute stand-up every day at 08:00 PM EAT for quick updates and blockages.
   >Development Updates (GitHub): All task tracking and code integration will be communicated through GitHub Projects    and Repository commits.

2. Asynchronous Updates:
   All task movements on the project board (To Do, In Progress, Done) must happen on the exact same day the work is completed. No batching on Friday.

3.Availability: 
Core collaborative working hours are 9:00 AM - 4:00 PM.

4. Deadlines & Commits
Commit Convention: type: description (Types: feat, fix, docs, style). No vague "wip" or "updated" messages allowed. (e.g., feat: complete JS logic for orders)
Code Freezes: All code for the MVP must be merged by Day 4 at 12:00 PM to allow for final testing and audit logging.

5. Conflict Resolution & Escalation
   >Technical Disagreements: The team will utilize a timeboxed debate and majority vote. In the event of a tie, Esther (Team Lead) has the final executive say to keep the sprint moving.
   >The Anti-Black-Box Rule: No task can be larger than 4 hours of active work. If it is, the assignee must break it down into smaller sub-tasks on the board.
   >Escalation Path: If any team member has 0 visible activity (commits, messages, or board moves) for 1.5 days, Esther will reach out directly via phone. If unresolved by Day 2, the team will reassign their tasks and formally note the absence in the audit log.
